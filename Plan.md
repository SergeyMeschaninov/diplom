
# План проверки и автоматизации приложения «Мобильный хоспис»

## Цели проекта
Закрепить навыки автоматизации тестирования мобильных приложений на Java с использованием UI Automator и CI. Реализовать ручное тестирование, автоматизацию ключевых сценариев, формирование отчётов Allure.

## Границы приложения
- В границах: авторизация, новости (список/деталь), pull-to-refresh, обработка ошибок сети, цитаты, «О приложении».
- Вне границ: серверная логика, push‑уведомления, внешние интеграции.

## Типы тестирования
- Функциональное тестирование.
- Тестирование UI/UX (навигация, читаемость, состояния загрузки/ошибок).
- Тестирование негативных сценариев (ошибки сети, пустые состояния).
- Регрессионное тестирование (после автоматизации).

## Этапы и шаги

### Этап 1. Подготовка окружения
1. Установить Android Studio и SDK (API 29).
2. Настроить эмулятор или подключить устройство (Android 10+).
3. Проверить переменные окружения (JAVA_HOME, путь к adb).
4. Скачать архив с приложением, установить APK.
5. Подготовить тестовые данные: логин login2, пароль password2.

### Этап 2. Ручное тестирование
1. Авторизация: вход с корректными/некорректными данными.
2. Навигация: переходы между экранами, кнопки «Назад», состояния загрузки.
3. Новости: список, детализация, изображения, даты, тексты.
4. Pull-to-refresh: свайп, индикация, обновление данных.
5. Ошибки сети: отключение интернета, повтор запроса, сообщения об ошибках.
6. Цитаты: отображение, прокрутка, реакции интерфейса.
7. «О приложении»: проверка версии, копирайтов, ссылок (если есть).
8. Заполнить чек‑лист и тест‑кейсы, отметить пройденные/непройденные.

### Этап 3. Автоматизация
1. Создать модуль для тестов (androidTest) в проекте.
2. Добавить зависимости UI Automator, JUnit, Allure (если требуется).
3. Определить классы-страницы (Page Objects) для основных экранов.
4. Написать автотесты для ключевых сценариев (авторизация, новости, pull-to-refresh, ошибки сети).
5. Добавить проверки (assertions) после каждого действия.
6. Настроить запуск тестов через Gradle.

### Этап 4. Отчётность и CI
1. Подключить Allure: зависимости, генерация отчётов.
2. Собрать результаты прогонов (allure-results).
3. Упаковать отчёт в allure-results.zip.
4. Сравнить время ручной проверки и автотестов, оформить Result.md.
5. Написать README.md: как запустить тесты, какие зависимости нужны, как собрать отчёт.

## Критерии готовности
- Проект собирается и запускается на API 29.
- Тесты проходят без дополнительных манипуляций.
- Есть UI‑автотесты на ключевые сценарии.
- Названия тестов и методов понятные.
- Отчёт Allure сформирован, упакован в архив.
